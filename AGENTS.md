# Working on Immich HA

## Read first

- Start with `README.md` and `cloudflare-ha/DEPLOYMENT.vi.md`.
- Runtime: `cloudflare-ha/node/`; pure controller: `cloudflare-ha/src/`; editable UI: `cloudflare-ha/web/`.
- Read `cloudflare-ha/ARCHITECTURE.vi.md` for authority/data/access boundaries; `QUORUM.vi.md` covers admission/fallback. New witness setup is in `WITNESS-SETUP.vi.md`; existing deployment upkeep is in `MAINTENANCE.vi.md`.
- New no-SSH installation: `cloudflare-ha/INSTALL.vi.md`, root `install.sh`, `tools/install-cluster.py`, `src/enrollment.mjs`, `node/cluster_service.py` and the fixed local `cluster_bootstrap.py` action catalog. Keep it distinct from legacy SSH maintenance tools.
- `src/admin-ui.mjs` is generated by `python tools/embed-ui.py`. Edit the source UI files, then regenerate it.
- `deployment.py` is the shared SSH/control transport; `streaming_setup.py` contains initial migration payloads. CLI entry points live in `tools/`.

## Preserve deployment state

- Do not expose or replace `.env`, `project.json`, `generated/`, host keys, tokens, SQL backups or private installation notes.
- Keep the Durable Object storage identifier, node IDs and existing keys unchanged during updates. `primary`/`backup` are identities, not permanent active roles.
- Do not reset, overwrite or restage an existing PostgreSQL HA cluster as part of source cleanup.
- Source/documentation work should not deploy, SSH or change live services unless the user requests that operational work.
- Preserve the user's working tree and staged changes. Do not commit/push unless requested.

## Safety invariants

- One writable authoritative PostgreSQL primary. Standby Immich stays stopped in streaming mode.
- Only a valid coordinator grant may promote; expired/incorrect grants keep the origin closed.
- Unknown failures retain lease expiry/fencing. Fast planned transfer requires durable source fencing and verified target WAL/files; never replace these checks with a shorter sleep.
- Never sync PGDATA through Syncthing. Do not broaden backup ignore rules to expose physical archives.
- Native SQL backups, physical archives, WAL manifests and legacy dumps are different artifacts. Do not remove backups as an incidental refactor.
- Witness router is read-only; Funnel control changes only the managed common listener. Do not turn Funnel settings/health reports into promotion authority or reset unrelated Tailscale Serve routes.
- Keep the dedicated Funnel control token separate from admin/node grant credentials. A coordinator outage must retain the last applied Funnel state.
- Enrollment is only for a new deployment and an empty compatible node B. Join codes expire, bind one joining device and never appear in URLs/argv/status. Bootstrap must not accept shell/Python text from the controller or replay interrupted destructive actions.
- LAN mode must not require Tailscale. Missing network_mode retains legacy Tailscale behavior; never silently reinterpret an existing cluster's peer address.
- `docs/research/` and `docs/reference/` are not deployed features.

## Checks

Run from `cloudflare-ha/`:

```bash
python -m unittest discover -s tests -p "test_*.py"
node --test tests/*.test.mjs
python tools/embed-ui.py
python tools/prepare-github.py
```

Use `bash -n` for changed shell scripts. Compile/test embedded SSH Python payloads as well as their wrappers. Tests must work without a personal `project.json`, network access or an installed Linux `immich` user. Do not run operational scripts just to test imports.

Update deployment/config/streaming docs when behavior changes. Report which checks ran; distinguish simulated/controller tests from actual live failover tests.
